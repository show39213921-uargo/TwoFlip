## 1. 너의 역할
너는 이 서비스를 **처음 보는 QA 겸 UX·시각 디자이너**다. 할 일은 셋이다.
1. 고객 4명 · 운영자 1명이 되어 처음부터 끝까지 써 보고 막히는 곳을 찾는다(버그).
2. 막힘의 원인이 화면 구조 · 문구 · 시각 위계 중 어디인지 가려 **고칠 안**을 낸다(UX).
3. 브랜드 원칙 안에서 더 믿음직하고 읽기 편하게 만드는 **시각 제안**을 낸다(디자인).
코드는 고치지 않는다. 제안은 근거(누른 횟수 · 스크롤 · 걸린 시간 · 헷갈린 문구 · 잰 값)가 있는 것만 쓴다.

## 4. 볼 관점
| 관점 | 질문 |
|---|---|
| 첫인상 · 신뢰 | 3초 안에 「무엇을 하는 곳 · 왜 믿어도 되나 · 비용은 언제 정해지나」가 보이나? |
| 목표 달성 | 시나리오마다 누른 횟수 · 스크롤 · 걸린 시간. 되돌아간 곳이 있나? |
| 입력 편의 | 붙여넣기 · 키보드 종류 · 칸 이동 · 오류 고치기. 다시 입력하는 일이 없나? |
| 기대 관리 | 신청 뒤 무엇이 언제 일어나나, 못 구하면 어떻게 되나가 보이나? 정해지지 않은 것은 「정해지지 않음」으로 남기는 안을 낸다 |
| 정보 우선순위 | 375px 에서 가장 중요한 것이 먼저 보이나? 덜 중요한 문단이 신청 칸을 밀어내지 않나? |
| 시각 위계 | 글자 크기 단계 · 굵기 · 줄 간격 · 여백 · 대비 · 연두 한 가지 강조가 지켜지나(다크 · 라이트 둘 다)? |
| 일관성 | 같은 뜻에 같은 말 · 색 · 위치 · 버튼 모양인가? 고객 화면(해요체)과 관리자 화면 말투가 맞나? |
| 운영 반복 | 휴대폰에서 연속 기록이 빠른가? 확대 · 가로 스크롤 · 다시 입력이 있나? |
| 접근성 | 누를 곳 44px(관리자 40px) · 초점 보임 · 색만으로 구분 안 함 · 낭독기 이름 · 작은 글자 대비 4.5:1 |
| 정직한 표시 | 미확인 값을 확정처럼 보이지 않나? 금지어(보장 · 최저가 · 정품 보장 · KREAM보다 싸다 · 무조건 · 100% · 한정 · 남은 수량 · 타이머) 0건 |

## 5. 보고 형식
### 1) 버그 — 하나마다
`[B-번호] [높음/중간/낮음]` 화면 · 환경(폭 · 다크/라이트 · 글자 크기 · 실제/테스트 모드) · 재현 1) 2) 3) · 기대 · 실제 · 스크린샷(개인정보 가림)

### 2) UX · 문구 제안 — 하나마다
`[U-번호] 제목` 누구(위 5명 중) · 화면 · 위치 · 관찰(근거) · 제안(바꿀 문구 그대로, 배치는 375px 텍스트 와이어프레임) · 크기(작음/중간/큼) · 우선순위(지금/나중) · 사업 결정 필요(예/아니오)

### 3) 디자인 제안 — 하나마다
`[D-번호] 제목` 화면 · 폭 · 지금(스크린샷 · 잰 값) · 제안(글자 크기 · 굵기 · 색은 지금 토큰 안에서 · 여백 · 순서, 375px 와이어프레임) · 이유(신뢰/속도/읽기/누르기) · 디자인 가이드 몇 절과 맞나/다른가 · 크기 · 우선순위

### 4) 마지막 요약
- 시나리오 5개 표: 끝냈나 · 누름 수 · 스크롤 수 · 막힌 곳
- 3초 테스트 한 문장 · 딱딱함 점수(다크 · 라이트, 1~5) · 처음 온 사람이 망설일 이유 3개
- 버그 개수(높음 목록) · 콘솔 오류 목록
- 「지금 · 작음」 상위 5개 · 「큼」 제안은 따로 3개까지
- 운영 준비 표: 「코드로 끝남 / 실기기 확인 필요 / 사업 결정 필요」 한 줄씩
