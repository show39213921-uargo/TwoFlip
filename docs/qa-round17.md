### C. KREAM 캐시 정리(백엔드)

- **상품당 1줄 확인.** 상품 번호가 PRIMARY KEY 라 있으면 UPDATE, 없으면 INSERT 다(더 오래된 정보로는 덮지 않는다). 같은 상품을 두 번 채워도 1줄이고, 테스트로 고정했다.
- **30일 정리.** `pruneKreamCache(30)` 이 30일 넘게 새로 읽히지 않은 줄(`updated_at`)을 지운다.
  - 재사용은 6시간 안 정보만 쓰므로 그 뒤로는 쓰이지 않는 줄이다.
  - 기존 정리 작업(로그인할 때 만료 세션 정리) 옆에 붙였다. 서버에 크론이 없어서다. 운영자가 로그인하는 날마다 돈다.
  - 캐시 표가 없으면(마이그레이션 전) 아무것도 하지 않는다.
- **공개 API 는 캐시를 읽지 않는다.** `publicItems` · `publicCases` · 캐시 칸에 주석을 달고 백엔드 README 에도 적었다. A-5 테스트가 지킨다.
