# TwoFlip 3차 UI/UX · 디자인 제안 (모바일 우선)

> Claude in Chrome(또는 사람)에게 이 문서를 **그대로** 넘긴다. 관리자 계정 비밀번호는 여기 적지 않는다 — 재영이 따로 전달한다.
> 1차 QA 지시서는 `docs/qa-prompt.md`. 이 문서는 10-14 저녁 반영분(2차 QA 수정 · **새 메뉴 「바로 구매」**) 이후 화면 기준이다.
> 2차 QA 에서 나온 버그·제안(B-1~B-4 · U-1~U-6 · D-1~D-5)은 아래 「이번에 바뀐 것」대로 반영했다 — 같은 번호로 다시 올리지 말고, 고쳐졌는지 확인만 한다.

---

## 너의 역할

TwoFlip 웹 화면을 **휴대폰 화면 위주로 직접 써 보고** 세 가지를 낸다.

1. **버그**: 동작이 틀린 것. 재현 절차와 함께 낸다.
2. **UI/UX 제안**: 동작은 하지만 고객·운영자가 헷갈리거나, 느리거나, 불안해서 그만두게 되는 지점과 그 개선안.
3. **소비자 편의 디자인 제안**: 고객이 신청 화면을 **믿고, 빨리, 편하게** 끝내도록 시각 디자인·배치·문구를 바꾸는 안.

코드는 고치지 않는다. 제안마다 근거를 붙인다. 근거는 어느 화면에서 무엇을 하다가 어디서 막혔는지다. 취향보다 **사용자가 목표를 이루는 데 걸리는 것**을 먼저 쓴다.

## 접속자는 대부분 휴대폰이다

고객은 KREAM 앱에서 「공유 → 링크 복사」를 하고 휴대폰 브라우저로 들어온다고 본다. 그래서 다음 순서로 본다.

- **기준 폭:** 360 · 375 · 390 · 430px 세로 화면이 1순위다. 1280px 는 깨지는지만 확인한다.
- **엄지 한 손:** 주요 버튼(신청하기, 사이즈, 동의)이 엄지가 닿는 화면 아래쪽에 있나? 누르는 곳이 44px 이상이고 서로 떨어져 있나?
- **키보드:** 칸을 누르면 키보드가 칸이나 오류 문구, 「신청하기」를 가리지 않나? 칸마다 맞는 키보드가 뜨나(주소 = URL, 휴대폰 = 숫자)? 다음 칸으로 넘어가기 편한가?
- **붙여넣기 중심:** 링크는 거의 항상 붙여 넣는다. 앞뒤에 글자가 붙은 공유 문구를 그대로 붙여도 되나?
- **느린 망·작은 화면:** 첫 화면에서 무엇을 하는 곳인지 바로 보이나? 스크롤을 몇 번 해야 신청 칸에 닿나? 스플래시가 기다리게 만들지 않나?
- **화면 확대·글자 크기:** 브라우저 글자 크기를 키워도 깨지지 않나?
- **모서리:** 아이폰 노치·홈 바, 안드로이드 하단 바에 버튼이 걸리지 않나?

브라우저 크기를 바꿀 수 있으면 위 폭으로 바꿔서 본다. 못 바꾸면 그렇다고 보고서 첫 줄에 적는다.

## 서비스 이해 (제안 전에 읽기)

- **무엇:** 고객이 KREAM 상품 링크를 남기면 운영자가 공식몰·근처 오프라인 매장·해외에서 그 상품·사이즈 재고를 직접 확인해 확보한다. 그런 다음 고객에게 연락해 KREAM 대신 넘겨주는 구매대행이다. 3명이 공동 운영한다.
- **흐름:** 신청 → (운영자) 탐색 중 → 확보 → 연락 완료 → 결제 완료 → 완료 / 취소
- **지금 단계:** 소규모 확인용 운영이다. 결제·배송·고객 계정은 아직 없고, 관리자 화면은 임시다.
- **정해지지 않은 것:** 가격·수수료 기준, 확보 실패 시 처리, 결제 방식, 고객 연락 수단, 수익 배분, 권한 체계. 제안은 해도 되지만 「정해졌다」고 가정하지 않는다. 제안에 이런 결정이 필요하면 그렇다고 적는다.
- **지킬 원칙:**
  - 확인하지 못한 값은 지어내지 않고 「미확인」으로 보인다.
  - 예상 수익이나 가격을 확정처럼 보이지 않는다.
  - 「KREAM 보다 싸다」 「마진 보장」처럼 보장하는 표현을 쓰지 않는다.
  - 디자인 제안도 이 원칙을 깨지 않아야 한다.

## 새 메뉴 「바로 구매」 — 이번에 가장 많이 볼 곳

운영자가 요청받은 상품을 구하러 갔다가 **더 좋은 상품을 먼저 사 두면**, 그 상품을 공개하고 고객이 「구매 요청」을 남기는 메뉴다.

- **고객 화면:** 신청 화면 헤더 「바로 구매」 → 상품 카드(사진 · 상품명 · 사이즈 · 판매가 또는 「가격 문의」 · 설명) → 「구매 요청」 → 아래에서 올라오는 시트(이름 · 휴대폰 · 요청사항 · 동의) → 요청 완료(접수번호 · 복사)
- **관리자 화면:** 맨 위 「신청 | 확보 상품」 → 「＋ 확보 상품 등록」(KREAM 주소 · 사이즈 · 판매가 · 매입가 · 공개 설명 · 사진 주소 · 내부 메모) → 상품 카드 → 구매 요청 목록에서 「이 요청으로 예약」
- **정해진 규칙(재영 결정, 재제기 말 것):**
  - 판매가를 정했으면 그 값, 아니면 「가격 문의」.
  - 같은 상품에 요청이 여러 개 오면 다 받는다. 운영자가 한 명을 골라 「예약 중」으로 바꾸면, 고객 화면 요청 버튼이 막힌다.
  - 사진은 KREAM 이미지를 쓰고, 필요하면 사진 주소(https)를 넣는다.
  - 메뉴는 같은 페이지 헤더 「바로 구매 | 신청하기」다.
- **정해지지 않은 것:** 결제 · 배송 · 예약 기한 · 예약 고객이 안 사면 어떻게 하는지 · 판매가 기준. 제안은 해도 되지만 정해진 것처럼 쓰지 않는다.
- **공개 화면에 절대 보이면 안 되는 것:** 매입가 · 내부 메모 · 다른 사람의 구매 요청(이름·번호). 보이면 **높음** 버그다.
- **보는 방법:** `?demo=1` 에는 샘플 3개(판매 중 · 가격 문의 · 예약 중)가 있다. 실제 화면은 상품이 하나도 없으면 「지금 바로 구매할 수 있는 상품이 없어요」, 서버 준비 전이면 메뉴째 안 보인다.

## 2차 QA 반영 — 고쳐졌는지 확인

| 번호 | 바뀐 것 |

| B-2 | 「KREAM 대비」는 신청 사이즈 시세로만 비교한다. 그 사이즈 시세가 없으면 「시세 미확인」이 나온다 |
| B-3 | 375px 관리자 카드 05 재고 기록이 표가 아니라 **기록마다 카드**로 나온다. 재고 셀렉트·✕ 를 가로 스크롤 없이 누를 수 있다 |
| B-4 | 배지에 「최저 …원 · 환율 필요 N곳」이 나온다 |
| U-1 | 「지금 신청하기」·헤더 「신청하기」를 누르면 주소 칸에 바로 커서가 간다 |

| U-3 | 신청하면 폼 자리에 접수 완료 카드(접수번호 · 복사 · 다른 상품 신청하기)가 뜬다 |
| U-4 | 오류가 뜬 칸은 입력 중에는 다른 오류로 바뀌지 않고, 맞으면 지워진다. 칸을 벗어날 때 다시 검사한다 |
| U-5 | 375px 접힌 카드에 「05 재고 기록하기」가 있고, 상태 숫자는 칩 한 줄이다 |

| D-3 | 스플래시는 약 0.6초다 |
| D-4 · D-5 | 히어로 버튼은 한 줄에 하나다. 표기는 TWOFLIP으로 통일했다 |

## 대상

| 화면 | 주소 | 비고 |
|---|---|---|
| 신청 화면(실제) | https://twoflip.u-argo.com | 신청이 **실제 서버 DB** 에 저장된다 |
| 신청 화면(테스트 모드) | https://twoflip.u-argo.com/?demo=1 | 신청이 이 브라우저에만 저장된다. **신청 흐름 테스트는 여기서 먼저 한다.** 끝낼 때 `?demo=0` |
| 관리자 화면 | https://twoflip.u-argo.com/admin.html | 로그인이 필요하다. 계정은 재영에게 받는다 |

## 반드시 지킬 것

1. **실제 신청 테스트용 값:** 이름은 `[QA] 이름`, 휴대폰은 `010-0000-0000` 만 쓴다. 실제 서버 신청은 **3건까지만** 넣는다.
2. **실제 고객 신청(이름에 `[QA]` 가 없는 것)은 보기만 한다.** 상태·재고·담당자를 바꾸거나 지우지 않는다.
3. **관리자 「설정」(지역·환율·유효 시간)은 3명이 같이 쓰는 값이라 바꾸지 않는다.** 검사 동작은 이렇게 본다.
   - 잘못된 값만 넣는다. 예: 유효 시간 `1400`, 환율 `-3` → 거절되는지 본다.
   - 확인이 끝나면 화면을 새로고침해 원래 값으로 되돌린다.
   - 저장 확인이 꼭 필요하면 원래 값과 **같은 값**을 다시 넣는다.
4. **바로 구매 실제 테스트:** 확보 상품은 **1개만** 등록한다. 공개 설명을 `[QA] 테스트 상품`으로 하고 판매가는 비워 「가격 문의」로 둔다. 다른 상품(실제 운영 상품)은 상태·예약을 바꾸지 않는다.
5. **정리:** 끝나면 관리자 화면에서 아래 순서로 지운다.
   - 「신청」 탭의 `[QA]` 신청을 모두 지운다(06 신청자 → 「이 신청 삭제」). 구매 요청도 여기에 「바로 구매」 표시로 들어와 있다.
   - 「확보 상품」 탭의 `[QA]` 상품을 지운다. 구매 요청이 남아 있으면 지울 수 없다 — 그 요청을 「신청」 탭에서 먼저 지운다.
5. **요청 제한:** 같은 IP 에서 신청은 10분에 5번, 로그인 시도는 10분에 10번까지다. 넘으면 「너무 잦습니다」가 나오는 게 정상이다.
6. **기록 금지:** 비밀번호·접속 키·실제 고객 이름과 전화번호를 보고서나 스크린샷에 남기지 않는다(가린다).

## 알려진 동작 (버그로 올리지 않는다, UX 제안으로는 된다)

- 실제 신청 화면에서 KREAM 상품 미리보기가 안 나오고 안내 한 줄만 보인다. 서버가 KREAM 을 읽지 않도록 꺼 둔 상태다. KREAM 정보는 접수 뒤 운영 쪽에서 채운다(최대 30분, 같은 상품은 6시간 안이면 바로 복사).
- 테스트 모드에서는 「테스트 모드에서는 KREAM 상품 정보를 불러오지 않습니다(서버 연결 후 표시). 신청은 그대로 진행할 수 있어요.」가 나온다.
- 관리자 화면의 공식몰·지도·해외 링크는 **검색 링크**다. 재고를 자동으로 조회하지 않고, 재고 기록은 전부 「수동」이다.
- 「KREAM 대비」 금액은 KREAM 수수료·배송비를 빼기 전 금액이다.
- 스플래시는 같은 탭에서 한 번만 나온다. 기기 설정이 「동작 줄이기」면 나오지 않는다.

## 사람과 시나리오 — 이 사람이 되어 써 본다

### 고객 「민지」 — 신청 화면, 휴대폰 (가장 중요)
- 20대다. KREAM 앱에서 사고 싶은 신발(270)이 너무 비싸서, 공유로 링크를 복사해 처음 들어왔다. 이 서비스를 모른다.
- 머릿속 질문:
  - 여기가 믿을 만한가? 누가 운영하나?
  - 얼마에 살 수 있나? 정말 KREAM 보다 싸나?
  - 언제, 어떻게 연락이 오나?
  - 내 번호로 뭘 하나?
  - 돈은 언제 내나? 안 구해지면?
- 목표: **1분 안에, 불안하지 않게** 신청을 끝낸다.
- 해 볼 것:
  1. 375px 로 첫 진입한다(스플래시 포함). 무엇을 하는 곳인지 몇 초 만에 알았나?
  2. 공유 문구째로 붙여 넣는다. `?size=` 가 있는 주소와 없는 주소를 둘 다 해 본다.
  3. 사이즈 → 이름 → 휴대폰 → 요청사항 → 동의 → 신청 순으로 채운다. 키보드 종류, 칸 이동, 가려짐을 본다.
  4. 접수 화면에서 「이제 뭘 기다리면 되는지」 알 수 있나? 접수번호를 어떻게 남겨 두나(캡처, 복사)?
  5. 일부러 틀린다: 다른 사이트 주소, 짧은 번호, 동의 빠뜨리기. 오류를 고치기 쉬운가?

### 고객 「현우」 — 신청 화면, 큰 글자·느린 망
- 40대다. 브라우저 글자 크기를 크게 쓰고, 지하철에서 신호가 약하다.
- 해 볼 것: 글자 크기를 키운 375px 화면, 네트워크 「느린 3G」(가능하면)에서 첫 화면 → 신청까지. 스플래시나 로딩 때문에 기다리는 시간, 깨지는 곳, 누르기 어려운 곳을 본다.

### 운영자 「민수」 — 관리자 화면, 매장에서 휴대폰
- 오프라인 매장에 서서 직원에게 재고를 묻고 바로 기록한다. 한 손, 375px, 이동 중이다.
- 목표: **그 자리에서 30초 안에** 「강남점 · 270 · 재고 있음 · 가격」을 남긴다. 다음 매장 기록은 더 빨라야 한다.
- 해 볼 것:
  1. 휴대폰으로 로그인한다(로그인 유지 체크).
  2. `[QA]` 신청을 검색해 찾는다.
  3. 05 에 기록을 2건 이어서 한다(종류·사이즈가 유지되는지).
  4. 한 건을 「품절」로 바꾼다.
  5. 상태를 「탐색 중」으로 바꾼다.

### 고객 「서연」 — 바로 구매, 휴대폰 (이번에 새로)
- 30대다. 친구가 보내 준 TWOFLIP 링크로 들어왔다. 특정 상품을 찾는 게 아니라 「지금 바로 살 수 있는 게 뭐가 있나」 둘러본다.
- 머릿속 질문:
  - 이건 신청과 뭐가 다른가?
  - 정품인가? 새상품인가?
  - 「가격 문의」면 얼마쯤인가?
  - 요청하면 바로 내 것이 되나?
  - 언제 연락이 오나? 「예약 중」은 무슨 뜻인가?
- 목표: **상품을 보고 30초 안에 구매 요청을 남기고, 다음에 무슨 일이 일어날지 안다.**
- 해 볼 것:
  1. 헤더 「바로 구매」를 누른다.
  2. 카드 둘러보기 — 판매 중, 가격 문의, 예약 중을 구분할 수 있나?
  3. 「구매 요청」 → 시트 → 이름·번호·동의 → 보내기 → 요청 완료.
  4. 시트를 닫고 같은 상품에 다시 요청해 본다. 막아야 하는지 제안한다.
  5. 예약 중 상품을 눌러 본다.

### 운영자 「재영」 — 확보 상품 등록·예약, 휴대폰과 PC
- 매장에서 요청받은 상품을 사면서, 더 좋은 상품을 하나 더 샀다. 그 자리에서 휴대폰으로 등록하고 공개한다.
- 목표: **1분 안에 등록 → 공개**하고, 요청이 들어오면 **한 명을 골라 예약**한다.
- 해 볼 것(실제 서버 — 「반드시 지킬 것」 4번 규칙대로):
  1. 「확보 상품」 → 「＋ 확보 상품 등록」에서 KREAM 주소 · 사이즈를 넣고 판매가는 비운다. 공개 설명 `[QA] 테스트 상품` → 「바로 판매 중으로 공개」 → 등록.
  2. 신청 화면 「바로 구매」에 보이는지 확인한다(KREAM 상품명·이미지는 최대 30분 뒤에 채워질 수 있다).
  3. 고객 「서연」으로 요청 1건 → 관리자 「확보 상품」에서 요청이 보이는지, 「신청」 탭에도 「바로 구매」 표시로 들어왔는지 확인한다.
  4. 「이 요청으로 예약」 → 고객 화면이 「예약 중」으로 바뀌고 버튼이 막히는지 본다.
  5. 상태를 「판매 중」으로 돌린다(예약 풀기 확인 창).
  6. 정리한다(「반드시 지킬 것」 5번).
- PC(1280px)에서는 신청 정리 흐름이 막히지 않는지만 짧게 본다.

```
화면·위치: 예) 신청 화면 375px, 주소 칸 아래 안내 줄
관찰(근거): 무엇을 하려다 어디서 막혔나 — 누른 횟수·걸린 시간·스크롤 횟수·헷갈린 문구

기대 효과: 예) 신청까지 스크롤 4번 → 1번
크기: 작음(문구·색·순서) / 중간(화면 한 곳 구조) / 큼(새 흐름·서버 변경)
우선순위: 지금 / 다음 / 나중
정해지지 않은 사업 결정이 필요한가: 예/아니오 — 예면 무엇
```

### 4) 마지막 요약
- 체크리스트 통과/실패 개수, 높음 등급 버그 목록
- **「지금 · 작음」 상위 5개**(바로 할 만한 것): U 와 D 섞어서 한 줄씩
- 모바일 시나리오 소요: 민지 신청 몇 번 누름·스크롤 / 현우 큰 글자에서 깨진 곳 / 서연 바로 구매 요청까지 몇 번 누름 / 민수 기록 1건·2건째 / 재영 확보 상품 등록 → 공개까지 몇 번 누름
- 첫 화면 3초 테스트: 처음 본 사람이 「무엇을 하는 곳」이라고 말할지 한 문장
- 「신청」과 「바로 구매」를 처음 본 사람이 구분할 수 있는지 — 한 문장
- 스플래시 판단(0.6초): 유지 / 줄임 / 없앰 + 이유
- 삭제한 `[QA]` 접수번호 · 확보 상품 번호 목록(지웠는지 확인용)과, 설정값·실제 운영 상품을 바꾸지 않았다는 확인
