# 26차 — 줄바꿈 · 링크 칸 안내 · 푸터 메뉴 통일(U-1 ~ U-3)

> 전체 QA 지시서(`docs/qa-full-review.md`) 뒤 첫 반영분. **프런트만 바뀐다**(백엔드 · SQL 없음 — 신청 · 조회 API · 토큰 규칙 그대로).
> 배치 · 색 · 토큰은 그대로다. 글자 줄바꿈 규칙 하나, 링크 칸 placeholder 와 안내 한 줄, 푸터 메뉴 넷만 바꿨다. 헤더 메뉴는 손대지 않았다(375 폭이 좁다).

## 안 바꾼 것
- 배치 · 색 · 토큰 · 문구 톤(placeholder 와 복사 방법 한 줄만 새 문구).
- 헤더 메뉴 셋(소개 · 바로 구매 · 신청하기) — 375 폭이 좁아 그대로.
- `config.js` PENDING · 사업자 정보 · 문의 창구(결정 대기).
- `#url-note` · `#url-hint` 의 문구와 보이는 조건, 링크 → 미리보기 → 사이즈 칩 흐름, 관리자 화면(`admin.css`).
- 백엔드 · SQL.

## QA 가 볼 것 (배포 번호 `?v=` 가 이번 커밋인지 먼저)
1. **375 홈(실제 모드 · 테스트 모드 둘 다)** — 링크 칸 placeholder 「KREAM 링크 붙여넣기」가 끝까지 보이고 「붙여넣기」 버튼에 가려지지 않는가. 칸 아래 「KREAM 앱에서 「공유 → 링크 복사」 후 붙여 넣어 주세요.」 한 줄. 첫 화면(812 높이)에 「이 상품 찾아 주세요」 버튼까지 들어오는가(로컬 실측 버튼 아래끝 701px).
2. 테스트 모드 `/?demo=1` — `https://kream.co.kr/products/1068133?size=270` 붙여넣기 → 복사 방법 줄 사라짐 · 「KREAM 상품 1068133 확인했어요 · 사이즈 270」 칩 · 「테스트 모드라 상품 정보는 불러오지 않아요.」 · 사이즈 칸 270 → ✕ → 복사 방법 줄 다시 보임 · 칩 · 안내 사라짐. 붙여넣기 버튼을 클립보드가 비었을 때 눌러 `#url-note`(「복사한 링크가 없어요 …」)가 전처럼 나오는가(회귀).
3. 실제 모드 홈 — 2번과 같은 흐름에서 미리보기(서버 kream_off 면 `#url-hint` 「상품명·가격은 접수 후 저희가 확인해요.」) 회귀 없음.
4. **375 바로 구매** — 제목 · 머리 안내 두 문장 · 점 네 줄 · 카드 안 글자에서 낱말 중간 끊김 0. 첫 페이지 · 소개 · 진행 상황 · 404 제목도 같이.
5. **푸터** — 다섯 페이지(`/` · `/about.html` · `/shop.html` · `/status.html` · 없는 주소 → 404) 아래 메뉴가 「신청하기 · 소개 · 바로 구매 · 신청한 상품 확인하기」 같은 순서. 404 의 넷이 모두 올바른 곳으로 가는가(없는 주소 `/x/y` 에서 열어 상대 경로 문제 없는지). 지금 페이지 링크에만 `aria-current="page"`.
6. 360 / 375 / 768 / 1280 × 다크 · 라이트 × 글자 200% — 가로 넘침 0 · 콘솔 오류 0. 200% 에서 진행 상황 단계 줄 「찾았어요」가 **칸 안에서 두 줄**로 끊기는 것은 의도(전에는 옆 칸으로 삐져나갔다) · 바로 구매 가격 「299,000 / 원」 두 줄은 전과 같음.
7. 관리자 `/admin.html` — 줄바꿈 · 글자 모양이 전과 같은가(이번 규칙에서 제외했는지 확인). 끝나면 [QA] 신청 삭제.

## 로컬에서 확인한 것
- `npm test` 173건 통과(167 + 푸터 6).
- 앱 브라우저 창에서 5개 페이지 × 360 / 375 / 768 / 1280 × 다크 · 라이트 × 글자 100% / 200%(총 80조합): `scrollWidth > clientWidth` 0 · JS 오류 0. 콘솔의 `ERR_CONNECTION_REFUSED` 3건은 로컬 백엔드(4410)를 안 띄운 실제 모드 API 호출 — 전과 같음.
- 375 다크 홈(테스트 모드): placeholder 「KREAM 링크 붙여넣기」 폭 144px, 글자 오른끝 202px < 붙여넣기 버튼 왼끝 261px · 복사 방법 한 줄 보임 · 버튼 아래끝 701px(첫 화면 안) · `body` `word-break: keep-all` · `overflow-wrap: anywhere` · `h1` `text-wrap: balance` 적용 확인.
- 흐름: 붙여넣기(값 넣기) → 복사 방법 줄 숨김 · 칩 「KREAM 상품 1068133 확인했어요 · 사이즈 270」 · `#url-hint` 「테스트 모드라 …」 · 사이즈 270 → ✕ → 복사 방법 줄 다시 보임 · 칩 · 힌트 숨김 · 붙여넣기 버튼 복귀.
- 낱말 중간 끊김 검사(모든 보이는 글자, 낱말마다 줄 수 측정): 360 · 375 × 100% 는 5개 페이지 모두 0. 200% 에서만 바로 구매 가격 「299,000 / 원」(숫자 뒤 「원」 앞 — `word-break: normal` 과 같은 자리, 전과 동일)과 진행 상황 4칸 단계 줄 「찾았어요」(360 은 「접수됨」 「마무리」도) — 칸 폭보다 긴 낱말을 칸 안에서 끊는 의도된 동작. 전에는(keep-all 만) 그 낱말이 옆 칸으로 넘쳤다(실측 `scrollWidth > clientWidth`).
- 푸터 넷 · `aria-current` 는 테스트와 375 바로 구매 화면(「바로 구매」에만 표시)으로 확인.
