# TWOFLIP 디자인 가이드

> 화면을 만들거나 고칠 때, 그리고 QA 의 디자인 제안(D-)을 판단할 때 기준이 되는 문서다.
> 2026-10-14 처음 작성. 지금 코드(`assets/css/app.css` · `admin.css`)에 **실제로 있는 값**을 정리한 「현재」와, 흩어진 값을 줄이는 「기준(목표)」을 같이 적는다.
> 「기준」 중 아직 코드에 적용하지 않은 것은 **§11 정리 계획**에 있다. 적용하면 이 문서의 「현재」를 같이 고친다.

---

## 1. 원칙

1. **모바일이 먼저다.** 고객 대부분은 KREAM 앱에서 링크를 복사해 휴대폰 브라우저로 들어온다. 375px 세로 화면에서 먼저 맞추고, 1280px 는 깨지지 않게만 한다.
2. **한 손 · 엄지.** 누르는 곳은 고객 화면 44px 이상, 관리자 화면 40px 이상이다. 주요 버튼은 한 줄에 하나만 둔다.
3. **정직한 표시.** 이 원칙은 디자인보다 앞선다.
   - 확인하지 못한 값은 「미확인」·「시세 미확인」·「가격 문의」로 보인다.
   - 예상 수익·차액을 확정처럼 크게 보이지 않는다.
   - 「KREAM 보다 싸다」 「정품 보장」 「마진 보장」 같은 비교·보장 문구는 쓰지 않는다.
4. **검정 · 흰색 · 연두 하나.** 브랜드는 무채색 위에 연두(`--lime`) 한 가지로 강조한다. 다른 강조색을 늘리지 않는다.
5. **움직임은 짧게.** 기다리게 하는 움직임은 0.6초를 넘기지 않는다. 기기의 「동작 줄이기」를 따른다.

## 2. 브랜드

### 워드마크

| 항목 | 규칙 |
|---|---|
| 파일 | `assets/img/twoflip-logo-white.svg`(흰 글자 · 500×80, 글자는 x 108~393) |
| 어두운 바탕 | 그대로 쓴다(헤더 · 관리자 헤더 · 스플래시) |
| 밝은 바탕 | `filter: invert(1)` 로 검게(신청 화면 푸터) |
| 높이 | 헤더 30px · 관리자 헤더 좁은 화면 24px · 푸터 22px. **22px 보다 작게 쓰지 않는다**(글씨가 얇아 300 굵기 — 흐려진다) |
| 정렬 | SVG 양옆 빈자리를 음수 여백으로 걷어 글자 왼쪽을 화면 여백(16·20px)에 맞춘다(`.logo-word`) |
| 표기 | 글로 쓸 때도 **TWOFLIP**(대문자). 「TwoFlip」 금지. 조사는 붙여 쓴다: 「TWOFLIP은」 |
| 금지 | 색 바꾸기(연두 등) · 늘이기 · 그림자 · 다른 글꼴로 다시 쓰기 |

### 스플래시

`assets/img/twoflip-splash.svg` 를 신청 화면 첫 진입(탭당 한 번)에만 쓴다. 전체 0.6초 안팎, 누르면 바로 끝, 「동작 줄이기」면 건너뛴다(`splash.js`). 관리자 화면에는 없다.

### 연두(`--lime` #c8f04a)

- **어두운 바탕 위에서만** 바탕색·글자색으로 쓴다(히어로 버튼 · 헤더 「신청하기」 · 히어로 강조 글자 · 다크 모드 기본 버튼).
- 연두 바탕 위 글자는 항상 `#0e0f12`.
- **흰 바탕 위 연두 글자 금지** — 대비가 모자란다. 밝은 바탕에서는 연두를 옅게 섞은 바탕(강조 줄 `color-mix(… 18~22%)`)으로만 쓴다.

### 기준

- 색은 **토큰으로만** 쓴다. 지금 코드에 박힌 값은 §11 에서 토큰으로 옮긴다.
  - 확인 필요(주황) `#f0a400` · `#9a6200` · `#ffc14d` → `--warn` · `--warn-bg`(새 토큰)
  - 연두 위 글자 `#0e0f12` 12곳 → `--on-lime`(새 토큰)
  - 어두운 바탕 테두리 `#343842` · `#1b1d22` → `--hero-line` · `--hero-surface`(새 토큰)
- 다크 모드는 토큰만 바꿔서 맞춘다. 화면마다 따로 고치지 않는다.

### 상태 색 — 하나의 규칙

신청 상태 · 재고 배지 · 확보 상품 상태가 지금은 화면마다 따로 칠해져 있다. 아래 네 갈래로 묶는다.

| 갈래 | 색 | 신청 | 재고 배지 | 확보 상품 |
|---|---|---|---|---|
| 가능 · 진행 좋음 | `--ok` | 완료 | 재고 있음 · 최저 | 판매 중 |
| 확인 필요 · 할 일 | `--warn` | 접수 · 탐색 중 | 재고 미확인 · 오래된 확인만 · 환율 필요 | — |
| 걸려 있음 · 사람이 붙잡음 | `--focus` | 확보 · 연락 완료 · 결제 완료 | — | 예약 중 |
| 끝 · 없음 | `--ink-3` | 취소 | 재고 없음 | 비공개 · 판매 완료 |

**색만으로 구분하지 않는다** — 항상 글자(「재고 있음」 등)를 같이 쓴다.

## 4. 글자

- 글꼴은 Pretendard Variable(`--font`), 숫자·번호는 `--mono`(접수번호 · 모델번호 · 사이즈 칩)다.
- 본문 줄 간격 1.6, 자간 −0.01em. 큰 제목은 자간 −0.03~−0.04em.
- **입력 칸 글자는 16px(1rem) 이상**이다. iOS 는 그보다 작으면 칸을 누를 때 화면을 확대한다.

### 크기 단계(기준)

지금은 24가지 크기가 흩어져 있다(.66~1.6rem). 7단계로 줄인다.

| 단계 | 크기 | 쓰는 곳 | 지금 흩어진 값 → 이 단계로 |
|---|---|---|---|
| display | `clamp(2rem, 4.6vw, 3.25rem)` · 800 | 히어로 제목 | 그대로 |
| title | 1.5rem(좁은 화면 1.2rem) · 800 | 구역 제목(진행 순서 · 바로 구매) | 1.5 · 1.35 · 1.6 |
| subtitle | 1.15rem · 700 | 카드·시트 제목 · 완료 카드 제목 | 1.05 · 1.1 · 1.15 · 1.2 |
| body | 1rem · 400~500 | 본문 · 입력 칸 · 버튼 | .95 · 1 |
| body-s | .9rem · 500 | 카드 본문 · 안내 · 관리자 본문 | .84 · .85 · .86 · .88 · .9 · .92 |
| caption | .8rem · 600 | 라벨 · 보조 정보 · 오류 문구 | .76 · .78 · .8 · .82 |
| micro | .72rem · 700 | 태그 · 배지 · 번호 머리 | .66 · .7 · .72 · .74 · .75 |

### 굵기

800(제목) · 700(버튼 · 강조 · 가격) · 600(라벨) · 500(보조) 네 가지만 쓴다.

## 5. 간격 · 모서리 · 그림자

| 항목 | 기준 |
|---|---|
| 간격 | 4의 배수 — 4 · 8 · 12 · 16 · 24 · 32 · 48. 화면 여백은 좁은 화면 16px · 넓은 화면 20px |
| 모서리 | 지금 12가지(5 · 6 · 7 · 8 · 10 · 12 · 16 · 20px …) → **5단계**: 6px(태그 · 칩) · 10px(입력 · 작은 버튼 · 기록 카드) · `--radius` 12px(버튼 · 패널) · `--radius-lg` 20px(카드 · 시트) · 999px(알약 — 상태 칩 · 헤더 버튼) |
| 그림자 | `--shadow` 하나(카드). 시트만 더 짙게. 버튼·입력에는 그림자를 쓰지 않는다 |

## 6. 부품

### 버튼

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 주 버튼(primary) | 밝은 바탕: `--brand`(검정) / **어두운 바탕: 연두** | 화면마다 가장 중요한 행동 하나 |
| 테두리(outline) | 투명 + `--line-strong` | 둘째 행동(다른 상품 신청하기 · 닫기 · 예약 중(막힘)) |
| 어두운 바탕 보조(ghost) | 투명 + 어두운 테두리 | 히어로 「어떻게 진행되나요?」 |
| 작은 버튼(btn-sm) | 관리자 전용, 좁은 화면 40px | 관리자 동작 |
| 위험(danger) | 글자 `--error` | 삭제 — 반드시 확인 창 |
| 글자 버튼(link-btn) | 밑줄 · `--focus` | 「지금 다시 확인함」 「보기」 — 좁은 화면 40px(§11) |

- 높이: 고객 화면 48px 이상(`.btn` · `.btn-block` 은 52px 안팎) · 헤더 44px · 관리자 40px.
- 문구는 동사로 끝낸다: 「신청하기」 「구매 요청 보내기」 「기록」 「저장」.
- 한 화면에 주 버튼은 하나만 둔다.
- **현재 상태(결정 필요):** 주 버튼 색은 바탕 밝기를 따른다. 라이트 모드에서 히어로는 연두, 신청 폼은 검정이다. 대비 때문에 생긴 규칙이다(흰 바탕 위 연두 버튼은 테두리 대비가 모자란다). 바꾸지 않는다면 그대로 두고, 바꾼다면 §11-③.

### 입력

- 라벨은 칸 위에 둔다. 칸 안 예시(placeholder)는 보조로만 쓴다.
- 칸 아래 순서: 안내(`.hint`, `--ink-3`) → 오류(`.error`, `--error`). 둘 다 `aria-describedby` 로 칸에 연결한다.
- 오류는 「보내기」를 누를 때 처음 띄운다. 그다음에는 입력 중에는 맞으면 지우기만 하고, 칸을 벗어날 때 다시 검사한다.
- 키보드: 주소 칸 `inputmode=url`, 휴대폰 칸 `tel`. `enterkeyhint` 는 마지막 칸만 done, 나머지는 next. Enter 는 다음 칸으로 넘기고, 보내지 않는다.
- 높이 48px 이상(고객) · 44px 이상(관리자 좁은 화면).

### 카드

| 카드 | 구성 |
|---|---|
| 신청 접수 완료 | 「접수 완료」 칩 → 제목 → 접수번호(mono, 크게) + 복사 → 다음에 일어날 일 한 줄 → 테두리 버튼 |
| 상품 카드(바로 구매) | 사진(정사각, 흰 바탕, contain) → 브랜드 한 줄 → 상품명 두 줄 → 사이즈 · 가격 → 설명 → 버튼. 예약 중이면 사진 흐리게 + 「예약 중」 깃발 |
| 관리자 신청 카드(접힘) | 사진 · 상품 · (좁은 화면) 사이즈·이름·시각·접수번호 · 재고 배지 · 상태 |
| 관리자 재고 기록(좁은 화면) | 판매처·✕ / 재고 셀렉트(전체 폭) / 가격·원화·KREAM 대비 / 종류·사이즈 / 확인 시각 |

### 배지 · 태그 · 칩

- **배지:** 상태 요약(재고 배지 등)이다. §3 상태 색, 한 줄(nowrap), 넘치면 말줄임하고 전체 문구는 title 에 둔다.
- **태그:** 덧붙임 정보(샘플 · 테스트 · 담당 · 바로 구매 · 다른 사이즈 · 오래됨)다. micro 크기를 쓴다.
- **칩:** 사이즈 · 모델번호다. mono 글꼴.

### 시트(아래에서 올라오는 창)

좁은 화면에서는 아래에 붙고 위 모서리만 둥글다. 홈 바 높이(`safe-area-inset-bottom`)만큼 띄운다. 넓은 화면에서는 가운데 둔다. 닫기 ✕ 는 44px이고, 바깥을 누르면 닫힌다. 맨 위에 무엇에 대한 창인지 요약(사진 · 이름 · 사이즈 · 가격)을 둔다.

### 빈 상태 · 안내 줄

- 빈 상태: 점선 테두리 상자와 「무엇이 없는지 + 다음에 할 일」 한 문장. 예: 「지금 바로 구매할 수 있는 상품이 없어요. 원하는 상품은 위에서 KREAM 링크로 신청해 주세요.」
- 안내 줄은 그 정보가 필요한 칸 바로 아래에 둔다(예: 「접수 후 확인」은 주소 칸 아래).

## 7. 화면 폭 · 배치

**페이지:** 구매 신청(`/`) · 바로 구매(`/shop.html`) · 관리자(`/admin.html`). 신청과 바로 구매는 다른 페이지다(10-14 재영 결정). 헤더 「바로 구매 | 신청하기」로 오가고, 지금 페이지 메뉴는 연두 글자(`aria-current=page`)로 표시한다. 바로 구매 페이지의 머리(`.page-hero`)는 히어로와 같은 어두운 톤으로 짧게 둔다.

| 폭 | 바뀌는 것 |
|---|---|
| ≤ 560px | 화면 여백 16 · 버튼 한 줄에 하나 · 히어로 그림 카드 숨김 · 진행 순서 가로 넘기기 · 상품 카드 2열 · 시트 아래 붙음 · 관리자 카드 3줄 · 재고 기록 카드 · 상태 숫자 칩 한 줄 |
| ≤ 880px | 히어로 1열 |
| ≤ 980px | 관리자 카드 사이즈·신청자 칸 숨김 → 상품 칸 아래 한 줄로 |

- **가로 스크롤 금지.** 예외는 「가로로 넘기는 한 줄」(진행 순서 · 상태 칩)뿐이고, 다음 칸이 살짝 보이게 해서 넘길 수 있다는 걸 알린다.
- 글자 크기 150% 에서도 깨지지 않아야 한다. 버튼 글자는 nowrap 으로 두고 폭을 넉넉하게 준다.

## 8. 문구

| 화면 | 말투 | 예 |
|---|---|---|
| 고객(신청 · 바로 구매) | 해요체 | 「확인 후 연락드려요」 「주소에 있던 사이즈(270)를 넣었어요」 |
| 관리자 | 합니다체 · 짧게 | 「저장했습니다」 「구매 요청이 있어 지울 수 없습니다」 |

- **정해지지 않은 것**(연락 시점 · 결제 · 예약 기한 · 판매가 기준)은 쓰지 않는다. 꼭 필요하면 「확보되면 연락드려요」처럼 정해진 범위까지만 쓴다.
- **표기:** 299,000원(쉼표 · 「원」 붙임) · 10.14 12:27(한국 시간) · 접수번호는 8자리 mono · KREAM · TWOFLIP 대문자.
- **오류 문구:** 「무엇이 틀렸는지 + 어떻게 고치는지」. 예: 「연락 가능한 휴대폰 번호를 적어 주세요. (예: 010-1234-5678)」. 화면에 맞게 쓴다 — 바로 구매 시트는 「신청」 대신 「구매 요청」(§11-⑦).
- **금지어:** 보장 · 최저가 보장 · 정품 보장 · KREAM 보다 싸다 · 무조건 · 100%.

## 9. 접근성

- 대비: 본문 4.5:1, 큰 글자·부품 테두리 3:1 이상.
- 포커스: `--focus` 테두리를 모든 누르는 곳에 보인다(`:focus-visible`).
- 이미지: 상품 사진 alt = 상품명, 꾸밈은 `alt=""`, 로고 alt = 「TWOFLIP」.
- 상태 변경 문구는 `role=status` · `aria-live` 로 읽힌다(접수 완료 · 저장됨).
- 움직임: `prefers-reduced-motion` 이면 스플래시·부드러운 스크롤을 끈다.

## 10. 움직임

| 쓰임 | 시간 |
|---|---|
| 누름 반응 · 색 바뀜 | .12~.15초 |
| 스플래시(전체) | 0.6초 안팎(가운데 .15 + 바꿔 끼우기 .1 + 이동 .35) |
| 로딩 뼈대(skeleton) | 반복. 움직임 줄이기면 멈춤 |

화면을 옮기는 스크롤은 「부드럽게」를 쓰되, **꼭 보여야 하는 결과(접수 완료 카드)는 바로 옮긴다** — 느린 기기에서 부드러운 스크롤이 멈추는 일이 있다.

## 12. QA · 디자인 제안을 판단할 때

- D- 제안은 이 문서의 원칙(§1)과 기준(§2~§10)에 맞는지 먼저 본다. 맞으면 §11 에 줄을 더한다.
