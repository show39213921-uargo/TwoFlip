# 24차 — 23차 QA 반영(U-1, 작음)

> 23차 QA(v=fa694437b398) 버그 0건 · 오픈 가능. 진행 상황 조회 직후 초점 한 건이다. **프런트만 바뀐다**(백엔드 · SQL 없음 — 조회 API · 잠금 · 요청 제한 · 토큰 규칙 그대로).
> 화면 배치 · 문구 · 색은 그대로다. `tabindex` · `role` · `aria-*` 와 초점 · 스크롤만 더했다.

## 안 바꾼 것
- 진행 상황 화면 배치 · 문구 · 색. 가격 · 판매처 · 이름 · 번호는 여전히 없다.
- 조회 API · 잠금(같은 접수번호 5번 틀림 → 10분) · 요청 제한(IP 10분 20번) · 토큰 규칙.
- 답 상자 초점(23차 U-4) · 단계 한 줄(23차 U-2).

## QA 가 볼 것 (실서버 — 조회 API 는 같은 IP 10분 20번이라 아껴 쓴다)
1. 실제 모드 `/status.html` — 키보드로 [QA] 신청 접수번호 · 0000 → Enter → 초점이 상품 제목 줄(`#st-title`, `tabindex=-1`) · 그 줄이 화면 안에 있는가.
2. 틀린 뒤 4자리(한 번만) → 오류 문장이 나오고 초점이 접수번호 칸 · 두 칸 `aria-invalid="true"` · `aria-describedby="status-error"`. 이어서 맞게 고쳐 Enter → 표시가 지워지고 1번처럼 제목 줄에 초점.
3. 빈 칸으로 「확인하기」 → 2번과 같은 초점 · 표시(서버 요청 없음).
4. 확인 링크(06 문구의 주소)로 바로 열기 → 초점이 옮겨지지 않는다(`body`).
5. 「동작 줄이기」 흉내(iframe 안 `prefers-reduced-motion: reduce`) → 조회 뒤 스크롤이 바로 이동(`scroll-behavior: auto`).
6. 회귀 — 답 상자 초점(구매할게요 → 결과 문장 · 답 바꾸기 → 구매할게요) · 단계 한 줄 · 잠금 문구 그대로. 360 ~ 1280 · 글자 200% · 다크/라이트 가로 넘침 0. 끝나면 [QA] 신청 삭제.
