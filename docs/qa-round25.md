# 25차 — 24차 QA 반영(U-1, 작음)

> 24차 QA(v=0f37d272cccc) 버그 0건 · 오픈 가능. 진행 상황 조회 칸을 빈 채로 「확인하기」 했을 때 문구 한 건이다. **프런트만 바뀐다**(백엔드 · SQL 없음 — 조회 API · 잠금 · 요청 제한 · 토큰 규칙 그대로).
> 배치 · 색은 그대로다. 화면 검사 문구 둘과 `aria-*` 를 붙이는 칸만 바꿨다.

## 바뀐 것

| 항목 | 어디서 | 무엇을 | 어떻게 확인 |
|---|---|---|---|
| U-1 빈 칸 문구 | 진행 상황(`status.html`) 조회 칸 「확인하기」 | 서버로 보내기 전 화면 검사에서 접수번호나 뒤 4자리가 비었으면 「접수번호와 휴대폰 번호 뒤 4자리를 적어 주세요.」 | 두 칸 비움 → 새 문구 · 초점 `#st-id` · 두 칸 표시 / 접수번호만 적음 → 새 문구 · 초점 `#st-last4` · 뒤 4자리 칸만 표시 |
| U-1 뒤 4자리 모양 | 같은 곳 | 뒤 4자리가 숫자 4개가 아니면(예: 3자리) 「휴대폰 번호 뒤 4자리를 숫자 4개로 적어 주세요.」. 칸이 숫자 아닌 글자를 지우므로 「12a」를 치면 칸에는 「12」가 남고 이 문구가 나온다 | 「12a」 → 「…숫자 4개로…」 · 초점 `#st-last4` · 그 칸만 표시 |

| 서버 요청 | — | 화면 검사로 걸리면 서버에 보내지 않는다(조회 횟수 10분 20번 · 5번 틀림 잠금에 안 들어감 — 전과 같음) | 네트워크 탭에 `/status/lookup` 요청 0 |

## 안 바꾼 것
- 진행 상황 화면 배치 · 색. 가격 · 판매처 · 이름 · 번호는 여전히 없다.
- 서버 쪽 오류 문구(어느 칸이 틀렸는지 말하지 않음) · 조회 API · 잠금 · 요청 제한 · 토큰 규칙.
- 24차 초점 동작(조회 성공 → `#st-title` · 확인 링크로 열면 옮기지 않음) · 23차 답 상자 초점 · 단계 한 줄.

## QA 가 볼 것 (실서버 — 조회 API 는 같은 IP 10분 20번이라 아껴 쓴다)
1. 실제 모드 `/status.html` — 두 칸 비우고 「확인하기」 → 「접수번호와 휴대폰 번호 뒤 4자리를 적어 주세요.」 · 초점 `#st-id` · 두 칸 `aria-invalid="true"` · `aria-describedby="status-error"` · `/status/lookup` 요청 0.
2. 접수번호만 적고 뒤 4자리 비움 → 같은 문구 · 초점 `#st-last4` · 뒤 4자리 칸만 표시(접수번호 칸에는 `aria-invalid` 없음) · 요청 0.
3. 뒤 4자리에 「12a」 → 칸에 「12」 · 「휴대폰 번호 뒤 4자리를 숫자 4개로 적어 주세요.」 · 초점 `#st-last4` · 그 칸만 표시 · 요청 0.
4. 접수번호를 지우고 뒤 4자리 0000 → 「…적어 주세요.」 · 초점 `#st-id` · 접수번호 칸만 표시.
5. [QA] 신청 접수번호 + 틀린 뒤 4자리(한 번만) → 「접수번호나 번호를 다시 확인해 주세요.」 · 두 칸 표시 · 초점 `#st-id`(24차와 같음) → 0000 으로 고쳐 Enter → 표시 지워짐 · 초점 `#st-title`.
6. 테스트 모드(?demo=1) demo0001 · 0000 으로 1~5 같은지. 회귀 — 답 상자 초점 · 단계 한 줄 · 확인 링크로 열면 초점 안 옮김. 360 ~ 1280 · 글자 200% · 다크/라이트 가로 넘침 0. 끝나면 [QA] 신청 삭제.
