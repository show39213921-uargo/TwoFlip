# TWOFLIP 정기 QA — 모바일 우선 (Claude in Chrome용)

> 매 회차 이 틀을 그대로 쓰고 **0번만 채운다**(회차 · 배포 번호 · 이번에 바뀐 것 · 특히 볼 것). 12차(10-15)부터 이 틀, 1~8번은 15차(10-15)에 고침, 5번은 16차 기준. 17차에 `qa-regular.md` → `qa-template.md` 로 이름만 바꿈(한 벌).
> 1~8번은 화면 · 규칙이 바뀔 때만 고친다. 관리자 비밀번호는 여기 적지 않는다.

## 0. 이번 회차 정보 (보내는 사람이 채운다)

- 배포 번호: ?v=____________ 이상 (페이지 소스에서 먼저 확인. 옛 번호면 강력 새로고침. 지난 회차 번호 그대로면 멈추고 재영에게 알린다)
- 이번에 바뀐 것: (항목별로 「어디서 · 무엇을 · 어떻게 확인」)
- 이번에 특히 볼 것:
- 관리자: 로그인돼 있는 세션을 쓴다. 없으면 멈추고 재영에게 로그인을 부탁한다.

## 1. 너의 역할
너는 오픈 직전·직후 서비스를 점검하는 QA 겸 UX 리뷰어다.
「이번에 바뀐 것」이 의도대로 됐는지 먼저 보고, 그다음 전체 회귀를 짧게 돈다.
제안은 근거(누른 횟수 · 스크롤 · 헷갈린 문구)가 있는 것만 쓴다. 코드는 고치지 않는다.

## 2. 서비스 한 줄
TWOFLIP은 고객이 KREAM 상품 링크를 보내면 운영자 3명이 공식몰·매장·해외에서 직접 구해 KREAM 대신 넘겨주는 구매대행이다.
- 첫 페이지(/): 히어로 자체가 신청서(링크 · 사이즈 · 이름 · 휴대폰 · 동의 · 「이 상품 찾아 주세요」)
- 소개(/about.html): 진행 방식 · 누가 하나요 · 자주 묻는 질문 · 최근 사례
- 바로 구매(/shop.html): 운영자가 먼저 구해 둔 물건에 「구매 요청」(바로 결제 아님). 운영자가 요청 하나를 골라 「예약 중」
- 관리자(/admin.html): 신청 · 찾아보기 · 05 재고 기록(좁은 화면은 한 손 기록) · 06 연락 문구 · 확보 상품 · 예약 · 사례 공개
고객 대부분은 휴대폰으로, 카카오톡·문자로 받은 링크를 눌러 들어온다.
기준 폭 375×812 → 360·390·430 → 마지막 1280.

## 3. 대상
| 화면 | 주소 | 비고 |

| 신청(테스트 모드) | https://twoflip.u-argo.com/?demo=1 | 이 브라우저에만 저장. 샘플 상품 3개 · 샘플 사례 3건 |
| 소개 | https://twoflip.u-argo.com/about.html | |
| 바로 구매 | https://twoflip.u-argo.com/shop.html | |
| 없는 주소 | https://twoflip.u-argo.com/abc/def | 404 화면 |
| 관리자 | https://twoflip.u-argo.com/admin.html | 로그인 세션 필요 |
⚠ 테스트 모드는 같은 탭에서 계속 켜져 있다. 실제 화면은 반드시 ?demo=0으로 들어가 노란 「테스트 모드」 띠가 없는지 매번 확인한다.

## 4. 반드시 지킬 것
1. 실제 신청 테스트 값: 이름 `[QA] 이름`, 휴대폰 `010-0000-0000`만. 실제 서버 신청은 한 회차 3건까지.
2. 실제 고객 신청(이름에 [QA] 없는 것)은 보기만 한다. 상태·재고 기록·담당자·사례 공개를 바꾸거나 지우지 않는다. 「다음 신청 →」으로 실제 카드를 펼치는 것까지는 된다.
3. 관리자 「설정」(지역·환율·유효 시간)은 바꾸지 않는다. 잘못된 값(유효 시간 1400, 환율 -3)이 거절되는지만 보고 새로고침으로 되돌린다.
4. 실제 공개 상품(지금 살로몬 L)은 상태·예약을 건드리지 않고, 구매 요청도 보내지 않는다. 요청 창은 열어 보기만 하고 닫는다.
5. 바로 구매 실서버 테스트가 필요하면 [QA] 확보 상품을 최대 1~2개만 등록한다(공개 설명 `[QA] 테스트 상품`, 판매가 비움, 「비공개」). 끝나면 지운다.
6. 05 재고 기록 테스트는 [QA] 신청에만, 판매처 이름은 `[QA] 매장 A`처럼.
7. 사례 공개 테스트는 [QA] 신청 1건으로만. 켜서 첫 페이지·소개에 뜨는 것을 확인하면 바로 끈다.
8. 연결 끊김 · 느린 망 · 사진 실패 · 클립보드 읽기(붙여넣기) 흉내는 테스트 모드(?demo=1)에서만 한다.
   - 예외: 관리자 「복사」 버튼 확인은 실제 모드 관리자 iframe 안에서 navigator.clipboard.writeText 만 덮어써서 해도 된다(서버 요청은 건드리지 않음). 보고서에 그렇게 적는다.
   - 주의: 실제 모드에서 fetch를 덮어써서 서버 요청을 막아도 신청이 서버에 들어간 적이 있다(6차). 실제 모드에서는 막기 흉내를 하지 않는다.
9. 요청 제한: 신청 10분 5번, 로그인 10분 10번(넘으면 「너무 잦습니다」가 정상). 공개 목록·사례 조회는 10분 600번이라 정상 사용에서 막히면 버그다.
10. 비밀번호를 입력하지 않는다. 비밀번호·실제 고객 이름·전화번호는 보고서·스크린샷에 남기지 않는다.
11. 「문자로 열기」는 누르지 않는다. sms: 주소만 확인한다. 찾아보기 링크로 열린 바깥 사이트에서는 아무것도 누르지 않고 닫는다.
12. 정리: 끝나면 관리자 「신청」 탭의 [QA] 신청·구매 요청을 모두 지우고(06 신청자 → 「이 신청 삭제」), 「확보 상품」 탭의 [QA] 상품을 지운다. 사례를 켰다면 꺼진 것부터 확인한다. 마지막에 관리자를 다시 불러와 [QA] 0건을 확인한다.

## 5. 알려진 동작 / 정해지지 않은 것 (버그로 올리지 않는다)
- 실제 모드는 KREAM 미리보기가 안 뜬다. 링크 확인 칩은 「KREAM 상품 ○○ 확인했어요」까지만, 그 아래 「상품명·가격은 접수 후 저희가 확인해요.」
- KREAM 정보(상품명·사진·브랜드)는 사무실 PC가 접수 후 최대 30분 안에 채운다(14차 실측 약 16분). 그 전에는 찾아보기 링크 · 「상품명 복사」가 없고, 연락 문구는 「상품(사이즈 L)」으로 나온다. 같은 상품의 최근(6시간) 정보가 있으면 바로 채워진다(16차부터 지운 신청 · 확보 상품이 채운 정보도 KREAM 캐시에 남아 재사용된다. 6시간은 KREAM 에서 읽은 시각 기준).
- 약속 한 줄은 콘텐츠 폭 344px 이상이면 한 줄, 그보다 좁으면 두 줄이다. 스크롤바 17px 가 있는 360 창(콘텐츠 343px)이 두 줄인 것은 의도다(실제 360 휴대폰은 한 줄). 줄 머리 「·」가 보이면 버그다.
- 공개 목록 · 사례는 브라우저가 60초 동안 다시 부르지 않는다(Cache-Control: public, max-age=60). 켜고 끈 뒤에는 1분 기다렸다 새로고침한다.
- 관리자 한 손 기록은 폭 560px 이하에서만. 바로 구매는 상품 1개면 큰 카드, 2개 이상이면 2열.
- 연락 문구 가격 줄은 일부러 「[가격을 적어 주세요]」다(재영 결정). 고친 문구는 새로고침하면 초안으로 돌아간다(저장 안 함).
- 국내 판매처(공식몰 · 오프라인)는 통화가 KRW 로 맞춰진다.
- 404 는 noindex 만 있고 og · canonical 은 일부러 없다.
- 동의 문구 2곳은 법적 문장이라 합니다체. 일부 주소 오류 문구(「…받습니다」)는 백엔드 공용 문장.
- 결정 대기라 화면에 없는 것: 운영자 이름·사진, 문의 창구, 결제 시점, 수수료, 「못 찾으면」 안내, 진행 상황 조회, 접수 알림, 파비콘·굵은 로고(파일 대기).
- 스플래시는 같은 탭에서 한 번, 「동작 줄이기」면 안 나온다.

## 6. 확인 방법 팁 (지난 회차들에서 쓴 방법)
- 폭: 창 크기를 못 바꾸면 같은 사이트 페이지 안에 iframe을 띄워 폭을 바꿔 본다(375 화면은 iframe 폭 392 = 스크롤바 17px 포함, 1280은 1297).
  보고서 첫 줄에 「어떻게 대신했는지」를 적는다.
- 글자 크기: iframe 문서의 html font-size를 16px → 24px(150%) → 32px(200%)로 바꿔 가로 넘침(scrollWidth - clientWidth)을 잰다.
- 라이트 모드 · 동작 줄이기: iframe 안 CSS의 @media(prefers-color-scheme: dark)를 끄고 (prefers-reduced-motion: reduce)를 켜는 방식으로 흉내 낸다. 브라우저 설정은 바꾸지 않는다.
- 확인 창(confirm): iframe 안에서는 window.confirm을 미리 덮어써서 피한다. 이미 떴으면 재영에게 「취소」를 눌러 달라고 한다.
- 찾아보기 링크: 미리 채움만 볼 때는 iframe 문서에 click 리스너(target=_blank 링크면 preventDefault)를 걸고 누른다. 새 탭 열림은 한 번만 실제로 눌러 보고 바로 닫는다.
  화면 좌표는 CSS 좌표와 다를 수 있다(배율). 좌표로 누르기 전에 스크린샷으로 위치를 먼저 맞춘다.
- [QA] 신청은 실제 공개 상품과 같은 KREAM 주소(products/1068133, 살로몬)를 쓰면 찾아보기 · 연락 문구 확인이 쉽다. 브랜드가 아직 없으면 01에 Salomon · LD0274200 을 넣고 「적용」.
- 안내 줄 · 결과 문장: MutationObserver 로 #src-note · role=status 글 변화를 모아 본다.
- 클립보드: 붙여넣기 흉내는 테스트 모드 iframe에서 navigator.clipboard.readText 를 덮어써 (정상 글 · 빈 글 · 거절 오류) 반응만 본다. 실제 권한 창은 「실기기 확인 필요」로 적는다.
- 공개 목록·사례 응답(https://wms.fivespace.kr/Testtwo/index.php/items · /cases)을 credentials 없이 불러 이름·번호·접수번호·가격·매입가·내부 메모·[QA] 판매처가 없는지 확인한다.
- 콘솔: read_console_messages를 한 번 호출해 추적을 켠 뒤 iframe을 지우고, 맨 위 탭에서 페이지들을 차례로 열고 다시 읽는다.
- 출력에 주소 쿼리 문자열을 그대로 찍으면 결과가 막힐 수 있다. 주소는 경로만 적는다.
- 화면 캡처 도구가 실패하면 요소 위치·문구 값으로 확인하고 그렇게 적는다.

## 7. 확인 순서
A. 「이번에 바뀐 것」 검증 — 항목별 통과/실패 + 근거
B. 전체 회귀(짧게)
  - 신청: 공유 문구(앞뒤 글자·줄바꿈) 붙여넣기 → 주소만 · ?size= 자동 입력 · 사이즈 L 유지 · 잘못된 주소 거절 ·
    붙여넣기 버튼 · 확인 칩 · 사이즈 칩(Tab 한 번 + 화살표) · 빈 제출 오류 5개(해요체) · 재신청 확인 창 ·
    완료 카드(접수됨 단계 · 0.3초 움직임 · 복사 44px · 「다른 상품 신청하기」 후 이름·번호 유지)
  - 첫 화면 스크롤 0번: 375×812에서 링크 칸 · 신청 버튼 · 약속 한 줄 · 「처음이세요? 이용 방법 보기 →」가 보이는가
  - 다른 페이지 「신청하기」 → 첫 페이지 링크 칸 초점
  - 바로 구매: 요청 창(보내기 하단 고정 · 바로 위 안내) · 뒤로 가기는 창만 닫힘 · 재요청 확인 창 · 「요청함 · 접수번호」 ·
    예약 중이면 「요청하신 상품이 예약 중이에요…」
  - 사례: 테스트 모드 샘플 3건(사진 · 「사진 / 준비 중」 · 못 찾음, 「n일 전」) · 실제 0건이면 구역째 숨김
  - 관리자: 찾아보기 링크 3개 · 복사 3개 · 05 미리 채움 · 한 손 기록 · 06 연락 문구 · 오래 기다린 순 · 알약 건수 · 「n시간째」 주황 ·
    고정 줄 「다음 신청 →」 · 「확보 상품으로 등록 →」 · 입력칸 초점 테두리 · 설정 잘못된 값 거절
  - 404 · og/canonical · ?v= 배포 번호 · 1분에 20번 오가도 목록이 막히지 않는가
  - 360 · 375 · 390 · 430 · 1280px × 글자 100 · 150 · 200%: 첫 페이지(신청 전 · 완료 카드) · 소개 · 바로 구매 · 404 · 관리자(카드 펼침) 가로 넘침 0
  - 금지어 0건: 보장 · 최저가 · 정품 보장 · KREAM보다 싸다 · 무조건 · 100% · 한정 · 남은 수량 · 타이머
  - 고객 화면 합니다체 0건(동의 문구 제외) · 콘솔 오류 0건
  - 다크 · 라이트: 어두운 머리 / 밝은 본문, 밝은 바탕 위 연두 글자 없음, 작은 글자 대비 4.5:1 이상(관리자 포함)
C. 판단 자료: 3초 테스트 한 문장 · 딱딱함 점수(다크·라이트, 1~5) · 처음 온 사람이 망설일 이유
